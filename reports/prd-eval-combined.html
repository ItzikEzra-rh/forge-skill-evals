03 — Journey

Timeline

Three sessions of experimentation, each building on the previous.

Session 1 — Initial Experiment

5-run PRD generation on OSAC-2135 (BMaaS)

Ran the same feature through 5 skill configurations (Eran's original, with PR#1 fixes, unattended without fixes, unattended with fixes, unattended with all fixes via local runner). Identified 7 gap types. Best run fixed 6/7 gaps. Built the local test runner and PR'd to Forge.

Session 2 — Head-to-Head Comparison

Skill A (Eran's) vs Skill B (Unattended) across 4 features

Ran OSAC-1110, 1269, 2872, 2917 through both skills. Skill A won all 4 (46/64 vs 28/64). Discovered the unattended skill's deeper research phase causes design leakage and problem statement contamination. Decision: invest in Skill A.

Session 2 — Evaluator Fixes

Fixed 6 JSON parse failures in the LLM judge

Increased max_tokens 1024→2048, added regex JSON extraction fallback, stronger system prompt. Added grade tiers (A/B/C/D). Zero failures after fix.

Session 3 — Clean Baseline

Fresh dataset, contamination-free, format-consistent

Discovered gold PRD format mismatch (2 of 4 golds used an old template format). Built fresh 7-case dataset using only new-template merged PRDs from enhancement-proposals. Removed exemplar contamination (2 test cases had their gold PRDs as skill exemplars). Fixed criteria to be format-agnostic.

Session 3 — Fix Iteration 1

Async status + Jira completeness checks

Elevated async status from guidance to mandatory check with explicit resource triggers. Added Jira completeness cross-check to self-review. Result: async status 1.1→1.7/2.

Session 3 — Fix Iteration 2

Scope accuracy, completeness, persona separation

Added no-scope-creep rule, scope inversion guard, scope creep self-review check, persona separation default. Result: +6 points total (67%→72%), but scope accuracy unchanged at 0.4/2.

04 — Key Discoveries

What We Found Along the Way

Several findings that changed how we evaluate and what we fix.

Gold PRD template mismatch inflated failure rates

  • 2 of the original 4 gold PRDs (OSAC-1110, OSAC-1269) used an old template format with numbered sections, "Goals and Non-Goals", FR-N requirements, Acceptance Criteria, and Risks
  • The skill correctly generates the current template (6 sections: Problem Statement, In Scope, Out of Scope, User Stories, Assumptions, Dependencies)
  • The judge penalized the skill for not matching the gold's format — template compliance scored 0.5/2 avg, but the skill was right
  • After switching to new-template gold PRDs: template compliance jumped to 2.0/2 (7/7 perfect)

Exemplar contamination leaked answers to the agent

  • The skill directory contains exemplar PRDs that the agent reads before generating
  • Two test cases (OSAC-2872, OSAC-2917) had their gold PRDs as exemplars — OSAC-2917 was byte-identical
  • Fixed by creating a clean skill copy with test-case exemplars removed for eval runs
  • This is important for Forge: if skills ship with exemplars, the eval dataset must not overlap with them

The unattended pipeline (Skill B) makes things worse, not better

  • Our multi-phase fork (ingest → exemplar selection → dimension triage → self-clarify → draft → review → revise) scored 28/64 vs Eran's 46/64
  • More research context caused design leakage (Helm charts, DaemonSets, protobuf conventions bleeding into the PRD)
  • Deeper context led to problem statement contamination (describing solutions instead of pain)
  • 70% more expensive per run ($8.50 vs $5 avg)
  • Decision: invest improvements in Eran's simpler pipeline, not the unattended fork

The judge itself had bugs that skewed results

  • 6 of 64 evaluations returned invalid JSON (Sonnet thinking out loud or response truncated)
  • All scored 0/2 by default, biasing results unpredictably
  • Fixed: max_tokens 1024→2048, regex JSON extraction fallback, stronger system prompt
  • After fix: zero failures across 120+ evaluations
  • One case (OSAC-2872 Skill A) jumped from 10/16 to 15/16 (Grade A) after the judge fix

08 — Next Steps

What's Left

Scope accuracy is the stubborn one. The model reads the Jira and extrapolates logical capabilities despite explicit "don't add scope creep" rules.

Priority 1 — Stubborn

Scope accuracy (0.4/2)

The model keeps adding In Scope items not in the Jira and inverting In/Out of Scope items. Rules didn't fix it — likely needs a structural pipeline change: have the agent explicitly list Jira requirements before drafting, then cross-check each In Scope item against that list. Or use exemplar-level calibration showing correct vs incorrect scope decisions.

Priority 1

Content completeness (1.1/2)

The Jira completeness cross-check exists but the model still misses specific capabilities. May need the same structural fix as scope — an explicit extraction step before drafting where the agent lists every requirement from the Jira, then checks off each one after writing.

Priority 2

Persona coverage (1.4/2)

Cloud Infrastructure Admin still gets dismissed as "Not affected" when the feature automates infrastructure work. The ownership test exists but the model doesn't always apply it. Could strengthen with feature-type-specific examples.

Priority 2

PR to eranco74/ai-skills

The fixes on our branch are ready to PR once we're satisfied with scope accuracy. Current improvements: async status +0.6, template 0.5→2.0 (eval fix), overall 67%→72%.

Priority 3

Expand eval dataset

14 new-template merged PRDs exist in enhancement-proposals. We test on 7. Adding more cases (especially networking features) would improve confidence in the fixes.

Priority 3

Merge test runner PR to Forge

forge#297 is draft. Needs review from Ella/Eran. The evaluator fixes (grade tiers, JSON fallback) are already in the PR.

The big question for scope accuracy

Instruction-level rules ("don't add scope creep", "trace each item to Jira") don't override the model's tendency to extrapolate. Two approaches to try:

  • Structural: Add an explicit "requirement extraction" step before drafting — the agent lists every In Scope and Out of Scope item from the Jira, then uses only that list when writing. Scope creep becomes visible as items not on the list.
  • Few-shot: Add calibration examples to the skill showing correct scope decisions vs common errors (e.g., "Jira says CRUD — scope is CRUD, not CRUD + monitoring + migration").

python3 devtools/test-skill/run.py \

06 — Criteria

Evaluation Criteria

The full criteria YAML that drives the judge. Each criterion gets an independent Sonnet call with the generated PRD, the gold standard, and this prompt.

generate-prd.yaml (full criteria config) 
skill: generate-prd
description: "PRD generation quality criteria"

gold_standard_file: gold-prd.md
generated_file_patterns:
  - "enhancements/*/prd.md"
  - ".artifacts/prd/*/03-prd.md"

judge_model: claude-sonnet-4-6

criteria:
  - id: persona-coverage
    weight: critical
    prompt: |
      Check if all 4 OSAC personas are addressed (Cloud Provider Admin,
      Cloud Infrastructure Admin, Tenant Admin, Tenant User). Each must
      have user stories or an explicit "Not affected" note.

  - id: persona-alignment
    weight: critical
    prompt: |
      For each user story, verify the capability matches the persona's role.
      Infrastructure ops → CIA, Tenant mgmt → CPA, Self-service → TU,
      Org config → TA. Misattributions are failures.

  - id: scope-accuracy
    weight: important
    prompt: |
      Compare In Scope / Out of Scope against gold standard.
      Flag inversions, missing items, and scope creep.

  - id: design-leakage
    weight: critical
    prompt: |
      Check for controllers, reconcilers, finalizers, playbooks, CRD fields,
      internal conditions. Platform vocabulary is acceptable.

  - id: problem-statement
    weight: important
    prompt: |
      Problem Statement = user pain + cost of inaction ONLY.
      No solution language ("introduces", "eliminates", "provides").

  - id: status-visibility
    weight: important
    prompt: |
      If async resource creation exists, status/progress visibility
      must be addressed in In Scope or User Stories.

  - id: template-compliance
    weight: important
    prompt: |
      Allowed sections ONLY: Problem Statement, In Scope, Out of Scope,
      User Stories, Assumptions (optional), Dependencies (optional).
      Evaluate against THIS spec, not the gold standard's structure.

  - id: completeness
    weight: important
    prompt: |
      Compare SUBSTANCE, not format. FR-N vs user stories is style.
      Flag substantive content gaps only.

pass_threshold: 6
fail_on_critical: true

Criteria we modified from the original

  • template-compliance: Changed to evaluate against the OSAC template spec, not the gold standard's structure. Some gold PRDs used an older template format — the judge was penalizing correct behavior.
  • completeness: Changed to be format-agnostic. "Missing FR-1 through FR-10" is a format difference, not a content gap, when the content exists as In Scope bullets.

08 — Contamination

Data Isolation

Steps we took to prevent the agent from seeing the answers. Verify these when adding new cases.

Three contamination vectors

VectorRiskMitigationStatus
Exemplar PRDs The skill ships exemplar PRDs the agent reads before generating. If an exemplar matches a test case, the agent copies the answer. Create a clean skill copy with test-case exemplars removed. Check: ls context/exemplars/ should not contain any test case keys. Fixed
Repo access On hosted Forge, the agent has access to cloned repos including enhancement-proposals (which contains the gold PRDs). The local runner only gives the agent the skill directory. No repo cloning, no git access, no web access. Safe
Context files Skill context files (osac-context.md, dimensions, review patterns) might reference test case content. Verified: no test case keys appear in any context file. Safe

How to create a clean skill copy

# Copy the skill directory
cp -r forge-skills/osac/generate-prd /tmp/eval-skill-clean

# Remove the eval dataset (agent shouldn't see test data)
rm -rf /tmp/eval-skill-clean/eval

# Remove exemplars that overlap with test cases
for case in OSAC-1319 OSAC-1330 OSAC-1332 OSAC-1567 OSAC-2540 OSAC-2872 OSAC-2917; do
  rm -f /tmp/eval-skill-clean/context/exemplars/${case}-prd.md
done

# Use /tmp/eval-skill-clean as --skill-dir in the runner
